## 一、底层配额逻辑：为什么你用 Codex CLI 写半天代码就撞墙？

很多刚从纯 IDE 补全插件切到 `Codex CLI` 的开发者会遇到一个困惑：明明早上只在网页端问了两个问题，为什么中午在终端里让 Codex 修了几个跨模块测试就提示达到窗口上限？

### 1. 网页端 + 本地终端 CLI + 云端异步任务 = 同一个订阅水池
当你在本地终端执行登录（关联个人 ChatGPT 订阅账号而非填入 `OPENAI_API_KEY`）时：
- **不产生额外的美元 API 账单**（这是包月制对高频程序员最大的福利）；
- 但每一次 Agent 循环（读取仓库目录树 → `ripgrep` 搜索调用链 → 推理修改方案 → 修改多个源码文件 → 运行 `pytest` / `vitest` / `tsc` → 读取报错堆栈再次推理修复）都会在后台消耗多轮高阶推理配额；
- 一个涉及 12 个文件修改和 3 轮单测自动修复的中型 PR，其等效推理消耗往往相当于网页端普通单轮问答的 **15～30 倍**。

### 2. 双重限流窗口设计
- **5 小时滚动窗口（Burst Window）**：限制半天内的峰值消耗，防止自动化死循环跑空算力；
- **7 天滚动总额度（Weekly Pool）**：决定你一周 5 个工作日能否从周一稳定干到周五下午不降速、不断粮。

## 三、算笔经济账：包月订阅（`5x` / `20x`）vs 绑卡按量烧 API Token

很多技术负责人会问：“我们直接给团队每人发一个中转 API Key 按 Token 扣费，是不是比开包月席位更省？”

我们按 **1 名主力全栈工程师每月 22 个工作日** 的真实 Agent 调用量测算：
1. **交互式开发（Agentic Coding）的上下文膨胀效应**：
   在本地运行 Codex CLI 时，每一轮 Tool Call（读文件、看 Diff、跑测试日志）都会携带长上下文反复请求旗舰推理模型。一名高频工程师平均每天在本地 CLI 消耗的输入+缓存+推理输出折算官方 API 原价通常在 **`$8 ～ $25 / 工作日`**，一个月 22 天轻轻松松烧掉 **`$180 ～ $450`（折合人民币 ¥1,300 ～ ¥3,200+）**，而且程序员心里总有“多跑一次测试又要扣几美金”的心理负担，反而不敢放手让 Agent 自动迭代验证。
2. **包月固定席位的确定性优势**：
   - 成本完全封顶可控：单席 `5x` 固定 **¥849/月**（含普票），重度 `20x` 单席 **¥1,499/月**（5 席及以上企业集采 **¥1,520/席/月，含 6% 增值税专票**，一般纳税人抵扣进项后净成本仅约 **¥1,433.96/席**）；
   - 心理零摩擦：工程师更愿意让 Codex 写完代码后自动补全边界单元测试、做静态类型检查与代码审查，代码交付质量显著提升。
3. **什么时候仍然必须用 API？**
   - 当你需要把大模型能力集成进**面向外部客户的线上生产环境业务接口（Production Backend）**、或跑高并发无人值守批处理流水线时，必须使用官方 API Platform 按量计费（严禁拿个人网页/CLI 订阅逆向转接生产业务接口，否则必触发账号封禁！）。

## 五、提升 Codex 配额利用率的 4 个工程小技巧

1. **善用项目根目录 `AGENTS.md`**：把仓库的包管理器命令（如 `pnpm test`）、目录分层约定、禁止修改的遗留模块写进 60 行以内的精简 `AGENTS.md`，可减少 Agent 每轮盲目遍历目录树浪费的探索轮次，实测可节省约 20%–30% 的无效配额消耗。
2. **用 `git worktree` 拆分原子任务**：不要在一个长达 80 轮的臃肿会话里同时改前端样式、后端 Schema 和 CI 脚本。每做一个独立子功能就新建干净会话，既降低上下文污染幻觉，又显著减少单轮上下文负荷。
3. **先让小范围单测跑通，再跑全量构建**：在提示词中明确要求 Codex 先运行目标模块的单个测试文件（如 `npx vitest run src/auth.test.ts`），最后一步再跑全量 `build`，避免每次微调都输出数千行全量日志挤占额度。
4. **严守「一人一号」底线**：切勿把一个 `20x` 账号同时登录在 3 个同事的电脑上并发跑 CLI——不仅 5 小时滚动窗口会瞬间打满互相抢占，还会因多地并发会话特征触发平台风控锁号。
